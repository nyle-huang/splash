    How the public stack works

    The deployment is intentionally split so the static site stays cheap, the broker keeps secrets and access control off the client, and the GPU worker only handles the narrow browser-facing contract.

    1. Static site

    GitHub Pages serves this frontend. The browser validates the selected file, resizes it client-side, and strips the data URL prefix before submitting the payload.

    2. Azure broker

    Azure Functions validates the bearer token, enforces size limits, forwards the job to Runpod, and exposes only two public endpoints: `POST /api/jobs` and `GET /api/jobs/{id}`.

    3. Runpod worker

    The GPU worker stages the uploaded image, runs the existing `business_prior` inference runtime, and returns either a compact final image payload or structured invalid-source details.
